# macOS 菜单栏重做设计

## 背景

菜单栏是普通用户唯一的非命令行入口。今天它有三个问题,都不是审美问题。

**开关藏得太深。** `.off` 状态下 "Start Protection" 是一行普通文字菜单项,夹在 View Logs 和
Run Doctor 中间;`.connected` 下的 "Turn Off" 压在菜单最底部。开或关要「点开菜单 → 翻到底部
找到那一项 → 再点」。而 macOS 自己的 Wi-Fi、蓝牙、隔空投送早就给了答案:**顶行一个开关**。

**点下去会把界面冻死。** `runPrivileged`(`main.swift`)用 AppleScript
`do shell script … with administrator privileges` **同步**执行 `bx up` / `bx down`,阻塞主线程
直到命令返回。2026-08-04 那次事故 `bx down` 卡了 71 分钟,那 71 分钟里菜单完全无响应、
一个字都没有。**把这个动作做得更醒目而不先解决阻塞,是负收益**——只会让用户更容易点到一个
会冻住的东西。

**用户真正会瞄的东西一个都没有。** 出口 IP 与地理位置、DNS 是否泄漏、IPv6 是否泄漏、
WebRTC 是否泄漏、UDP 走哪个中继——这些是代理用户每天检查的项,菜单里全部缺席,现有的
7 行里有 "Network changes"、"Active"、"Version" 这类信息密度极低的行。

## 设计

### 一、菜单栏图标:形态承担信息

**更正(2026-08-07,实现阶段①后核对代码)**:本节初稿称「菜单栏图标是 template image,
颜色不由我们做主」——**那是错的**。现有实现 `compactStatusImage`(`main.swift:232`)设
`isTemplate = false`,自己填 `.systemGreen`/`.systemYellow`/`.systemRed`,颜色一直是能用的。
template 只是一个**可选**模式(纯 alpha,系统按浅色/深色和高亮态自行上色),不是硬约束。

选择形态编码的真实理由有两条,与「能不能上色」无关:

1. **用户明确要求**:「可以不用颜色,但也要有不同形态」。
2. **形态比颜色稳**。非 template 图标不随菜单栏高亮态反色、不随深色模式适配,在浅色菜单栏
   上一个深色图标和深色菜单栏上同一个图标观感差别很大;而 8px 的彩色圆点在色觉障碍、
   小尺寸、以及菜单栏被壁纸干扰时都不可靠。轮廓在这些条件下全部成立。

颜色**保留为可选加强**(实心盾仍可着绿),但不承担信息——去掉颜色后四态必须仍然可分。

| 状态 | 形态 | 运动 |
|---|---|---|
| 已保护 | 实心盾 | 4 秒一轮极慢呼吸(仅透明度 1 → 0.45) |
| 已关闭 | 空心盾,1.35pt 描边,62% 不透明 | 完全静止 |
| 切换中 | 实心盾 | 1.5 秒一轮脉冲(透明度 + 缩放) |
| 需要注意 | **盾沿中线锯齿裂开成两半,两半错位** | 4 秒一轮呼吸 |

三条正交线索:**填充轻重 · 裂开 · 运动**。任一条单独都足以区分,颜色只作可选加强。

裂缝走中线而非边缘:边缘咬一个口可能被读成造型,**裂穿中线只可能是「坏了」**。两半分别
平移(左半 −0.65, −0.15;右半 +0.65, +0.3 并旋转 2°),读起来是已经滑开,而不是画了一条线。

**验收标准是 16pt**,不是放大图。若裂缝在 16pt 下糊成一团,减少锯齿段数并加宽缝隙。

### 二、两种呼吸,两个用途

- **稳态**(已保护):4 秒一轮,**只动透明度**,幅度小到不盯着看注意不到。用途是瞟一眼确认
  它活着,不是吸引注意。低频率也意味着可忽略的耗电。
- **过渡态**(连接中 / 断开中):1.5 秒一轮,带缩放,开关滑块停在**中间位**同步呼吸。此时
  用户在等,界面必须持续说话。

`prefers-reduced-motion` 下全部停止动画,改用静态区分(过渡态降低不透明度)。

### 三、菜单结构

```
┌──────────────────────────────────┐
│ 🛡 已保护              [ ●━━ ]  │  头部:判决 + 开关同一行
│    45.76.12.8  ⧉                 │  出口 IP,可复制
├──────────────────────────────────┤
│ 出口位置          🇯🇵 日本·东京  │
│ 线路                 reality·vps │
│ 延迟                      390 ms │
│ DNS 泄漏                  已保护 │
│ IPv6 泄漏                 已阻断 │
│ WebRTC                    未泄漏 │
│ UDP 中继               hysteria2 │
│ 速度          ↑2.1 ↓8.7 MB/s    │
│          最后检查:刚刚           │
├──────────────────────────────────┤
│ 重新检查                     ⌘R  │
│ 复制报告                     ⌘C  │
├──────────────────────────────────┤
│ 重新连接 / 查看日志 / 运行诊断    │
│ 设置…  ⌘,  /  退出 bx  ⌘Q       │
└──────────────────────────────────┘
```

**头部把开关和判决放在同一行**,因为 bx 自己就是那个代理——只读监视器不需要开关,bx 需要。
**出口 IP 放在最显眼处并可复制**:它是代理用户最常看、最常要拷走的一个值(报问题、验证位置、
贴给别人)。

每行带一个单色图标,便于扫读;国家用国旗 emoji,零阅读成本。

**「退出 bx」在所有状态恒在。** 这修掉一个已记录的缺陷:今天 `quitBxActionTitle` 只出现在
`.connected` / `.warning` 两个分支,其余状态菜单里没有任何退出入口。

### 四、诚实规则(三条,不可让步)

**1. 一条时间戳,而且它必须是真的。** 底部只写「最后检查:刚刚」,前提是 **⌘R 重新检查会把
这一组全部重跑**,包括 WebRTC 这类浏览器侧检查。显示绿勾而实际是三天前查的,正是本项目反复
在修的那类谎。

**2. 三态,不是两态。** 值 / 异常值 / **「未观测」**。「未观测」不计入异常计数,也不触发裂开
图标。把「没问出来」压成失败,就是重新制造 `internal/observe` 专门要消灭的那个谎
(`Tristate` 零值为 `Unknown` 正是为此)。

**3. 观测不覆盖信念。** 实测与状态不符时,头部判决仍按 bx 相信的状态渲染,附加说明另起一行。
与 `bx status --json` 并列发布 `desired` / believed / `observed` / `divergence` 的原则一致。

两种「坏」在形态上必须不同:

- **单项泄漏**(如 WebRTC):只有那一行变,其余照常,头部写「1 项异常」。
- **劫持整个失效**:头部 IP 直接换成真实 IP 并标注,出口位置显示真实国家,多一行说明。

后果完全不同的两件事,不该长成一个样子。

### 五、授权模型变更

今天菜单每次开/关都经 AppleScript 弹一次管理员密码框。改为:**菜单以普通用户身份连
Guardian 控制 socket,Guardian 按 `owner_uid` 授权。**

这条路的地基已经存在并已在生产使用:

- `peercred_darwin.go` 的 `localPeerCredentials` 用 `LOCAL_PEERCRED` / `GetsockoptXucred`
  取对端 uid,是真实的 peer-cred。
- `localapi.go` 已有判据 `credentials.uid == 0 || (ownerUID != 0 && credentials.uid == ownerUID)`,
  今天守着 `/v1/recoveries`——**路径恢复会重装路由,是实打实改网络的操作,它已经允许
  owner 免密调用**。
- `owner_uid` 在 `sudo bx setup` 时写进 config,那次已经要求过管理员密码。

**改动范围精确到一个函数**:`mutationHandler`(`localapi.go`)服务 `/v1/up` 与 `/v1/down`,
把 `credentials.uid != 0` 换成与恢复同款的 owner 判据。`updateHandler`(`/v1/update`)与
`migrationHandler`(`/v1/migrate`)**保持 root only** —— 装卸与版本迁移低频、后果重,
本来就该在终端里带 sudo 做。分界线是「日常操作 vs 系统变更」,不是难度。

**已知并已接受的后果**:在没有 Apple Developer ID 的前提下,无法把这个权利绑定到 Bx.app
(SMJobBless 之类的绑定要校验双方代码签名)。因此**该用户下的任何进程都能静默开关 bx**。
项目所有者在明确知晓此后果后选择现在就做。待取得 Developer ID 后按
`2026-07-20-macos-unified-app-design.md` 的 Phase 3 收紧。

### 六、异步与进度

开关经 socket 调用后,菜单立刻进入过渡态,**全程不阻塞**:

- 开关滑块停中间位并呼吸,头部显示「正在断开…」+ **已用秒数**。
- 超过 20 秒追加一行「比预期久,通常 3 秒内完成」并给出 Guardian 日志入口。
- 失败时就地展开原因,带上 `guardianCodeHints` 的失败码指引(如
  `core_ownership_uncertain` 会提示 `sudo bx down && sudo bx up`),不再是只写
  "bx did not stop" 的模态框。

### 七、轮询

今天菜单**每 5 秒 spawn 两个进程**(`bx --version` + `bx status --json`),而 macOS 上
`bx status --json` 已包含完整观测(两次 `route -n get` + 一次 `networksetup` + 控制 socket
往返),观测本身封顶 5 秒——几乎满占空比,且无人查看时同样在跑。

改为:**菜单打开时 2 秒一次,关闭时 30 秒一次**(关着时只有图标需要更新)。

## 数据来源盘点

写进设计的每一行都必须说清数据从哪来。

| 行 | 现状 |
|---|---|
| 线路 / 传输 | ✅ `status --json` 已有 |
| 延迟 | ✅ 已有 `latency_ms` |
| UDP 中继 | ✅ 已有 `udp.transport` |
| DNS | ✅ 配置已知;`internal/observe` 另经 `networksetup` 实测归属 |
| 速度 ↑↓ | ✅ `internal/stats` 有 `bytes_up` / `bytes_down` 累计计数器,采样求速率 |
| 捕获接口 / 劫持是否生效 | ✅ `internal/observe` 已实测(`route -n get`) |
| **出口 IP 与地理位置** | ❌ **新建**:经隧道打一次 IP 回显 |
| **IPv6 泄漏实测** | ❌ **新建**:今天只有「已装 v6 阻断路由」的信念,没有实测 |
| **WebRTC** | ⚠️ **只能是时点检查**:浏览器内的行为 bx 观测不到,靠 `bx webrtc-check` 跑一次 |

WebRTC 那行永远随最后检查时间一起呈现,绝不作为常驻实时指示。

## 拆分与顺序

三个阶段,各自独立可交付、可验证。

**① 授权与异步(前置)**
Guardian `mutationHandler` 认 `owner_uid`;菜单改走 Guardian socket,不再 AppleScript;
开关动作异步化 + 已用时 + 逾时提示 + 失败码指引。**当天就改善现有菜单**,不等新 UI。

**② 菜单主体**
图标四形态 + 两种呼吸;头部(判决 + 出口 IP + 开关);数据行(**先只上今天有数据的行**);
「退出 bx」恒在;轮询按打开状态调频。

**③ 检测能力**
出口 IP 与地理位置、IPv6 泄漏实测、`bx webrtc-check`;⌘R 全量重检把这一组统一刷新并盖上
同一个时间戳;⌘C 复制报告。

顺序不可调换:② 的开关依赖 ①;③ 的行在 ② 里先以「未观测」占位,数据到位后自然点亮——
这正是三态设计的直接好处。

## AI-native 落点

**⌘C 复制报告**输出的是**给 agent 读的结构化快照**:`desired`(意图)/ believed(信念)/
`observed`(事实)/ `divergence`(差异),而非截图式文本。用户遇到问题时贴给 agent,对方拿到
的不是一句「连不上」,是一份可直接推理的状态机快照。

这不需要在菜单里多加任何一个字,并与「agent 只声明意图、从不直接驱动动作」自洽:agent 读
报告并给建议,动手的仍是用户点那个开关。

## 本期不做

- **不做 popover 面板。** 用原生 `NSMenu`,自定义视图只用在头部和开关行——macOS 自己的
  Wi-Fi / 蓝牙菜单正是这么做的。
- **不做吞吐曲线。** 速度以一行文本呈现。bx 是安全工具不是监控工具,曲线不是用户打开它的理由。
- **不做右键菜单分工。** 左键出菜单,就一个菜单。
- **不碰 Linux / Windows。** 菜单栏是 macOS 独有;Windows 托盘另有其设计
  (`2026-07-12-windows-tray-app-design.md`)。

## 测试策略

- **纯逻辑单测(Go)**:owner 授权判据(owner / root / 其它 uid / 取不到 peer-cred 四种情形)、
  三态渲染判定、异常计数不含「未观测」、逾时阈值。
- **Swift 单测**:四形态图标 path 生成、呼吸参数、菜单在全部状态下**均包含退出入口**
  (这是回归守卫,对应已记录的缺陷)。
- **回归守卫**:`mutationHandler` 放开后,`updateHandler` / `migrationHandler` 仍拒绝非 root
  ——必须有独立测试钉住,否则一次「顺手统一一下」就会把装卸也放开。
- **真机验收**:免密开关一次点通;断开途中菜单保持可交互并显示秒数;拔网线制造异常,
  确认图标裂开且头部不改口。

## 风险

**授权放宽后,该用户下任何进程都能静默关掉 bx。** 已明确告知并被接受,见「授权模型变更」。
缓解:Guardian 日志记录每一次 up/down 的发起 uid 与时间,事后可追溯。

**16pt 下裂缝可能不可读。** 验收以真实尺寸为准,不可读则减少锯齿段数并加宽缝隙;
最坏情况退回「实心盾 + 缓慢闪烁」,仍不依赖颜色。

**出口 IP 检测要发网络请求。** 频率必须低(菜单打开时最多一次,且有缓存与最小间隔),
否则每次打开菜单都对外发包既慢又是指纹。检测目标不得使用 china 列表内的域名
(`ifconfig.me` / `ip.sb` 会被正确直连,测出来的是错的——这个坑 2026-06-29 踩过)。
