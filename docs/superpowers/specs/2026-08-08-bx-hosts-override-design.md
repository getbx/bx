# bx hosts 覆盖设计

## 背景

用户要把一个 app 的云端依赖换成本机服务(VibeBoard 的语音识别:app 把
`wss://torchfun.com/v1/voice` 编译进了二进制,配置里的 relay 地址是摆设)。标准做法是改
`/etc/hosts` 指向本机,但**在 bx 开着时不成立**:

- app 走系统解析器,而 bx 把系统 DNS 接管到 `127.0.0.1`(实测:VibeBoard 不硬编码
  `127.0.0.1:53`,监听假 DNS 全程零查询——它读系统解析器);
- bx 的 DNS 返回 fake-IP(`198.18/15`),TUN 在底层把这条连接吃进去,按域名决定走代理
  还是直连,最后送到真 torchfun。

**`/etc/hosts` 根本没进入这条链路。** 用户试过的 lo0 别名抢路由也被 TUN 捕获盖过。也就是
说:凡是应用的流量,DNS 与路由都归 bx 管,任何在 bx **外面**做的重定向都拦不住它。

结论是结构性的:**能把某个域名引到本机的地方,只有 bx 自己。**

## 这不是为某个 app 开的后门

「把某域名钉到某 IP」是代理工具的标准能力(Clash 的 `hosts`、sing-box 的 DNS rules)。
bx 缺它反而是个洞:**只要 bx 在跑,`/etc/hosts` 对被 bx 接管的应用就是失效的**,而用户
并不知道——他会以为自己改了却没生效,像这次一样绕四层(hosts + lo0 别名 + 自签证书 +
独立 sing-box)才发现问题在哪。

## 机制已经存在

`internal/dns/server.go:119`,DNS 处理的**第一跳**:

```go
if addrs := s.staticA[domain]; len(addrs) > 0 && q.Type == dnsmessage.TypeA {
    return s.staticAResponse(h, q, addrs)   // 直接返回固定 A,连 fake-IP 都不进
}
```

今天只从传输服务器域名填充(`supervisor/run.go:285`,为防环),**没有配置面**。本设计
就是给它开一个口子,不新造机制。

## 为什么 `127.0.0.1` 真的会落到本机服务

两道保证,都已核实:

1. **内核路由**:`127.0.0.0/8 → lo0` 比 bx 装的 `0.0.0.0/1` 前缀更长,最长前缀匹配 →
   环回流量根本不进 TUN。
2. **就算进了**:`127.0.0.0/8` 在 `route.DefaultPrivateCIDRs`(`router.go:16`)里,恒直连,
   不受 global 模式影响。

## 设计

### 配置

`/etc/bx/config.yaml` 顶层加一个映射,与 `server`/`rules`/`udp` 平级:

```yaml
hosts:
  torchfun.com: 127.0.0.1
  api.example.com: 192.168.50.10
```

值是单个 IPv4 字面量。**不支持 CNAME、不支持通配符、不支持多值**——本期只解决「把一个
域名钉到一个 IP」,多值与通配的语义(轮询?顺序?最长匹配?)需要单独想清楚,现在加进来
只会造成误解。

`bx setup` 换传输时不会动它:`setup.UpdateTransports` 是 `yaml.Node` 外科手术,只改指定键。

### 三条安全约束(全部要有测试)

**1. 传输服务器的静态 A 不可被覆盖。** `staticA` 里那些条目是防环用的——bx 的隧道子进程
靠它们解析到服务器真 IP,再由 bypass 路由送出去。用户若把服务器域名映射到别处,隧道会
连到错误的地方,而且**是静默的**。冲突时以传输服务器为准,并在启动日志与 `bx status`
里明说这条 hosts 被忽略了。

**2. 只接受 IPv4 字面量。** 非法值(域名、IPv6、空串、`0.0.0.0`)在**加载配置时**就报错拒绝
启动,而不是运行期静默丢弃。理由:`staticA` 是 DNS 第一跳且不受 `rules` 影响,一个悄悄
没生效的覆盖,用户会以为生效了——正是本功能要消灭的那种困惑。

**3. AAAA 不受影响。** `staticA` 只处理 `TypeA`;被覆盖域名的 AAAA 查询照旧落到默认路径成
NODATA(bx 对全局 v6 fail-closed)。这正是想要的:逼应用走 v4,不给它一条绕过覆盖的路。

### 可见性

`bx status` **常驻一行**显示生效中的覆盖:

```
  覆盖    torchfun.com → 127.0.0.1  (1 条)
```

没有覆盖时不显示这一行(字段缺席是诚实的「没有」,不是每次都提醒「你没配」)。

这条不是锦上添花。`staticA` 是 DNS 第一跳、**不受任何 `rules` 影响**:写错一个域名就把它
整个劫持了,而且没有任何规则能救回来。一个写完就忘的隐形开关,是这类功能最常见的事故源
——用户几个月后发现某网站打不开,不会想到是自己当初加的一行。

`bx status --json` 同步加字段,便于 agent 与诊断包读取。

### 与观测层的关系

`internal/observe` 是只读观测层,回答「系统现在实际是什么样」。hosts 覆盖属于**意图**
(用户显式声明的配置),不是观测到的事实,所以放在 `bx status` 的信念侧,与 `server`、
`transport` 同类。不进 `observed`。

## 本期不做

- **通配符与多值**(`*.example.com`、一个域名多个 IP)。语义要想清楚,且今天没有需求。
- **热重载**。改了 hosts 要 `sudo bx down && sudo bx up`,与改 `server` 一致。
- **CNAME / 其他记录类型**。
- **Linux/Windows 特殊处理**。这是纯 DNS 层改动,平台无关;`staticA` 本来就是三平台共用。

## 已知取舍:与 bx 的生命周期绑定

bx 关掉时这条覆盖随之失效,应用会解析到真域名。对本次的用例(本地语音识别)意味着
**bx 停 = 语音回到云端**。这不是新增的坏处:实测已确认该 app 走系统解析器,bx 关掉后
`bx down` 会还原系统 DNS,应用解析到真 torchfun 并按原样失败——**回到今天的状态,而不是
多坏一样东西**。

但要如实告诉用户这一点,不能让人以为「配了就永久生效」。

## 测试策略

- **纯逻辑单测**:配置解析(合法/非法值各若干)、与传输服务器域名冲突时的取舍、
  大小写与尾点归一化(`Torchfun.com.` 与 `torchfun.com` 必须同一条)。
- **DNS 层单测**:被覆盖域名的 A 查询返回固定 IP 且**不进 fake-IP 池**;AAAA 仍为 NODATA;
  未覆盖域名行为不变。
- **回归守卫**:传输服务器域名不可被用户 hosts 覆盖——这条若失效,隧道会静默连错地方,
  是本设计最危险的失败模式。
- **真机验收**(由用户执行):配置 `torchfun.com: 127.0.0.1` → `bx up` →
  `dig torchfun.com @127.0.0.1` 返回 `127.0.0.1` → app 的语音落到本地 ASR 服务器 →
  `bx status` 能看见那一行 → 其他域名(如 `api.ipify.org`)出口仍是 VPS。

## 风险

**一个错的覆盖没有任何规则能纠正。** `staticA` 在 fake-IP 与 `rules` 之前。缓解是加载期
严格校验 + `bx status` 常驻显示,而不是靠用户记得自己配过什么。

**覆盖到公网 IP 时,路由决策退化成按 IP 判断。** 因为不进 fake-IP,就没有域名可供
`route.Router.Decide` 使用。映射到私网/环回没有这个问题(恒直连)。文档要写明。
