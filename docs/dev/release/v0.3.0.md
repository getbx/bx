# bx v0.3.0

上一个正式版是 **v0.2.7(2026-07-16)**,之后 **582 个提交**。

**版本号是 0.3.0 而不是 0.2.8,因为这一版改变了流量的去向** —— 见下面第一节。
一个会改路由的版本不该被标成补丁。

---

## ⚠️ 升级前先读:三条行为改动

这三条都是**修复**,但它们会让流量走到与 v0.2.7 不同的地方。如果升级后你发现
某些应用的行为变了,先看这里,再怀疑网络。

### 1. 你写的 direct / proxy 规则现在对 UDP 也生效

v0.2.7 里,`rules` 只管住 TCP —— UDP 在判定的第一步就短路了,而 `udp.mode`
**默认就是 proxy**,所以每一个用默认配置的人,他写的直连规则都只管住了一半流量。
而 Apple / iCloud / Steam / 微信这些最常见的直连目标恰恰重度用 QUIC。

**现在 UDP 与 TCP 走同一条判定。** 如果你给某个域名配了强制直连,它的 QUIC
流量从这一版起也会直连 —— 那是你当初写那条规则时要的效果。

**china 列表刻意仍然不对 UDP 生效**(那是 bx 塞进去的一万两千条默认,把它的
作用域扩到 UDP 是单独一个决定)。这一条由测试钉住,不会悄悄变。

### 2. 局域网 UDP 不再被送进隧道

`私网恒直连` 是 bx 一直声明的不变量,而 UDP 从来没有遵守过它 —— mDNS、AirPlay、
打印机发现、SMB 这些全被塞进了隧道。现在它们直连。

### 3. macOS:直连出口会自愈

v0.2.7 之后修过一次「bx 自己的直连到不了公网」(所有 direct 规则 100% 失败,
而隧道健康、状态显示 Protected)。本版进一步:每 30 秒**问一次内核**那条
scoped 默认路由还在不在,不在就重装 —— 而不是只在换网时才重装。

真机上验过一次完整的故障与恢复:`直连 776(失败 243)` → `26(失败 0)`。

## 升级方式

**请用 dmg 重新安装,不要用 `bx update`。**

pre-1.0 的已知行为:旧版客户端对新包跑 `bx update --package` 会解包失败并干净
报错。它不会弄坏什么,但也不会升级成功。

1. 下载 `bx-macos-arm64.dmg`(本版第一次真的会生成它,见「修复」)
2. 拖 Bx.app 进 Applications,打开
3. 它会引导完成安装;**你的连接配置一个字都不改**

Windows 用 `bx-setup.exe`;Linux 用 tar.gz。

## 新功能

### 多服务器:看得见、换得了、测得出

- `bx server list` / `--test` / `bx server use` / `bx server rm`,菜单里也有
- 换服务器走 **commit-confirmed**:武装 → 等新隧道健康 → 确认;起不来就地回滚。
  v0.2.7 那句「立即生效」是假的 —— 它只武装不确认,而 Core 随后会自动回滚
- **延迟与探活**:按需测,而且量的是「你 → 那台」的真实往返(经 Core 的直连
  拨号器,否则量到的是「你 → 当前服务器 → 目标」,一个看起来正常的假数字)
- **吞吐**:从你已经产生的流量里被动统计,按服务器记历史并**标出年龄**

### 一条命令把 bx server 装到裸 VPS

`bx server deploy <user@host>` —— 远端自取二进制并用本机验过签的校验和核对、
装 reality+hysteria2、放行 ufw、起服务、打出可粘贴的 setup 命令。
**bx 一行 SSH 凭据都不经手**(密码/密钥/agent/known_hosts 全归系统 ssh)。

菜单里也有:填表 → 交给 Terminal 执行。

### 具名出口(mesh 用不了时的退路)

`bx egress add/route/ls/rm` —— 把点名的网段交给一条已经存在的隧道
(比如 `ssh -D 1080` 开的 SOCKS5)。**白名单**,只有写出来的网段走它。

能用 Tailscale 就用 Tailscale(bx 不挡它的 subnet router,已验证);这是 mesh
穿不过去时的那条退路。

### 诊断

- **`bx doctor` 现在答得出「流量到底成不成」**:直连/代理的成败、成片失败的
  用户规则(点名到 config 里那一行)、UDP 的状况
- **`bx status` 会点名成片失败的规则**,并给出正确的下一步 —— 直连出口坏掉时
  它会说「不是你的规则」,而不是让你去删一条正确的规则
- **泄漏检测新增一条**:浏览器语言与出口国不符(时区那条本来就有)
- **`go run ./cmd/bx-acceptance`**:一条只读命令答出「这台机器上这一版真的在
  工作吗」。它在开发者自己的机器上第一次跑就抓到「文件换了、进程没换」

### 菜单栏

规则/服务器/部署三个窗口重做:一组一行、坏消息在前、没话说就不说。
新增**卸载入口** —— 此前菜单里一个都没有,而把 Bx.app 拖进废纸篓只会删掉界面,
Guardian 仍以 root 在跑、保护仍然开着。

## 修复(挑影响最大的)

- **macOS 的 DirectDialer 一直到不了公网** —— 所有用户 direct 规则 100% 失败,
  而隧道毫发无伤、状态一路 Protected。存在了很久,直到 bx 开始**数**失败才显形
- **UDP 的失败一次都没被数过** —— 一条每次拨号都失败的 UDP 传输,在 status 里
  是一片安静
- **Guardian**:孤儿启动标记、所有权锁存、维护挂起、升级把机器停在「保护已关、
  文件已换、服务没起」—— 61 个修复,大多来自真机事故
- **dmg 第一次真的会生成**。README 一直写着「安装(推荐用 .dmg)」,而打包脚本
  从来没调用过做 dmg 的那个脚本 —— 每个拿到包的人都被指向一个不存在的文件
- **Bx.app 第一次有图标**。此前 Finder / Launchpad / Spotlight 全画灰色占位方块
- 构建产物不再污染 Spotlight(搜 "bx" 会出来五个 Bx.app,点开是陈旧的构建)

## 已知限制

- **本版只在 macOS 上做过真机验证。** Windows 与 Linux 的改动(dialer 判定路径、
  UDP 计数、具名出口)只过了 CI 与单元测试
- `bx update` 从 0.2.7 升级不可用,见上面「升级方式」
- macOS 上仍然没有代码签名,首次打开会提示「无法验证开发者」——
  系统设置 → 隐私与安全性 → 「仍要打开」
